# Music Backend

A Spring Boot REST API for a music player. The current version stores song metadata in PostgreSQL and supports creating songs, listing songs, and fetching a song by ID.

**Status:** In development. The song metadata API is implemented; audio upload, streaming, and playback are not implemented yet.

## Getting started

### Prerequisites

- JDK 21 configured through `JAVA_HOME`.
- Docker Desktop with its Linux engine running, or Docker Engine with Compose.
- Available host ports `5432` for PostgreSQL and `8080` for the API.
- Network access to download Maven and project dependencies on the first build.

Run the following commands from the project root. Examples use Windows PowerShell; on macOS/Linux, replace `.\mvnw.cmd` with `./mvnw`.

### 1. Configure credentials

Create a `.env` file beside `compose.yaml`:

```dotenv
DB_USERNAME=music
DB_PASSWORD=replace_with_your_local_password
```

Choose your own password. `.env` is ignored by Git.

Compose substitutes these values into `POSTGRES_USER` and `POSTGRES_PASSWORD`. Spring Boot imports the same file through `application.properties`.

The application currently connects to:

```text
jdbc:postgresql://localhost:5432/music
```

Compose runs only the database. The Spring Boot application runs on your host machine.

### 2. Start PostgreSQL

```powershell
docker compose up -d
docker compose ps
docker compose logs postgres
```

Wait for PostgreSQL to report that it is ready to accept connections.

The container is named `music-postgres`. Its data is persisted in the Compose-managed `music_pgdata` volume, mounted at `/var/lib/postgresql` for PostgreSQL 18.

### 3. Prepare the schema

The application uses `spring.jpa.hibernate.ddl-auto=validate`: it checks the existing schema at startup and does not create tables. There are currently no versioned database migrations.

For a **new, empty development database**, open a database session using the username from `.env`:

```powershell
docker compose exec postgres psql -U music -d music
```

Create the table expected by the current entity:

```sql
CREATE TABLE songs (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    duration_seconds INTEGER NOT NULL
);
```

Exit with `\q`. If your database already contains this table, inspect or restore its schema instead of running the creation statement again.

A database in Docker is separate from a PostgreSQL database installed on your machine, even if both are named `music`. Existing tables and records must be exported and restored if you want to move them into Docker.

### 4. Run the API

```powershell
.\mvnw.cmd spring-boot:run
```

Alternatively, run `MusicApplication` in IntelliJ IDEA with the project root as the working directory so the `.env` file is found.

Check the running application:

```powershell
Invoke-RestMethod http://localhost:8080/api/health
```

Expected response:

```text
Backend is running
```

## API reference

Base URL: `http://localhost:8080`

| Method | Endpoint | Purpose | Success status |
| --- | --- | --- | --- |
| `GET` | `/api/health` | Basic application response | `200` |
| `GET` | `/api/songs` | List all songs | `200` |
| `GET` | `/api/songs/{id}` | Get a song by ID | `200` |
| `POST` | `/api/songs` | Create a song | `201` |

The health endpoint returns plain text. Song endpoints return JSON. The list endpoint currently has no pagination or explicit sort order.

### Create a song

```powershell
$body = @{
    title = "First Song"
    durationseconds = 210
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
    -Uri http://localhost:8080/api/songs `
    -ContentType "application/json" `
    -Body $body
```

Example response (the ID is generated by the database):

```json
{
  "id": 1,
  "title": "First Song",
  "durationSeconds": 210
}
```

**Field naming:** The current request uses `durationseconds`, while the response uses `durationSeconds`.

Validation and mapping behavior:

- `title` must be present and nonblank. Leading and trailing whitespace is stripped before saving.
- Request validation permits up to 200 characters, but the entity maps to a 100-character database column. Until these limits are aligned, use titles of at most 100 characters.
- `durationseconds` must be a positive integer and cannot be null.
- Requests rejected by Bean Validation return HTTP `400`.

### List songs or fetch one

```powershell
Invoke-RestMethod http://localhost:8080/api/songs
Invoke-RestMethod http://localhost:8080/api/songs/1
```

The list endpoint returns an array of song responses, or `[]` when no songs exist. Fetching a missing ID returns HTTP `404` through `SongNotFoundException`.

## Project structure

```text
src/main/java/com/senagh/music/
|-- MusicApplication.java       # Application entry point
|-- Controller/                # HTTP endpoints
|-- service/                   # Application operations and repository calls
|-- Repository/                # Spring Data JPA repository
|-- Entity/                    # Database entity mappings
|-- dto/                       # API request and response records
|-- mapper/                    # Request/entity/response conversion
|-- exception/                 # Domain exceptions and HTTP status mapping
`-- config/                    # Startup repository check

src/main/resources/
`-- application.properties     # Datasource and JPA configuration

src/test/java/com/senagh/music/
`-- MusicApplicationTests.java # Spring application-context test

compose.yaml                   # Local PostgreSQL service and volume
pom.xml                        # Dependencies and build configuration
```

`SongController` delegates to `SongService`. The service uses `SongRepository` for persistence and `SongMapper` for conversions:

```text
CreateSongRequest -> SongMapper.toEntity() -> Song -> repository.save()
Saved or retrieved Song -> SongMapper.toResponse() -> SongResponse -> JSON
```

The mapper strips title whitespace when creating an entity. Database lookups, saves, and missing-song handling remain in the service.

`RepoCheck` runs on application startup and prints the song count and existing song metadata to the console.

## Development and testing

```powershell
# Compile the application
.\mvnw.cmd compile

# Run the current test suite
.\mvnw.cmd test

# Build the executable JAR (also runs tests)
.\mvnw.cmd package

# Run the packaged application
java -jar target/music-0.0.1-SNAPSHOT.jar
```

The current suite contains a single `@SpringBootTest` context-loading test. It uses the application datasource configuration, so PostgreSQL must be running with valid credentials and the expected schema. Dedicated controller, service, and persistence tests have not been added yet.

To stop the local database while retaining its data:

```powershell
docker compose down
```

Adding `-v` removes the named database volume and its stored data.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Docker reports a missing `dockerDesktopLinuxEngine` pipe | Start Docker Desktop and wait for its Linux engine to be ready. |
| Port `5432` is already occupied | Check whether a local PostgreSQL service is running. Stop it if appropriate, or change the Compose host port and the application's JDBC URL together. |
| Password authentication fails after changing `.env` | PostgreSQL initialization variables apply only to a fresh data directory. Update the existing database role/password or use its original credentials. Recreating the container alone does not reset volume contents. |
| Expected tables are missing | Confirm the host, port, and database. A Docker database does not automatically contain tables from your local PostgreSQL server. |
| Startup reports schema-validation errors | Prepare or restore the schema; `ddl-auto=validate` will not create or update it. |
| Credentials are not resolved | Check `.env`, the application's working directory, and any environment variables or IDE run-configuration overrides. |
